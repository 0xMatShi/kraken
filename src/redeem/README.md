# Polymarket Auto-Claim Bot

Автоматический бот для клейма выигрышей на Polymarket для событий типа "updown-15m".

## Возможности

- Автоматический поиск ближайших событий по выбранной монете (BTC, ETH, SOL, XRP)
- Ожидание завершения события
- Автоматическое определение победителя
- Gasless клейм через Polymarket Relayer
- Бесконечный цикл мониторинга и клейма

## Требования

### Переменные окружения (.env)

Необходимо создать файл `.env` в корне проекта со следующими переменными:

```env
POLYGON_PK=<ваш_приватный_ключ_кошелька>
POLY_API_KEY=<api_key_от_polymarket>
POLY_API_SECRET=<api_secret_от_polymarket>
POLY_API_PASSPHRASE=<api_passphrase_от_polymarket>
```

### Зависимости Python

Установите зависимости:

```bash
pip install -e .
```

Или вручную:

```bash
pip install aiohttp python-dotenv web3 python-dateutil websockets
pip install poly-eip712-structs py-builder-relayer-client py-builder-signing-sdk
```

## Использование

### Запуск

```bash
cd src/redeem
python claim.py
```

### Интерфейс

При запуске вы увидите меню:

```
============================================================
💰 POLYMARKET AUTO-CLAIM BOT
============================================================

Выберите монету для отслеживания:

  1. BTC (btc-updown-15m)
  2. ETH (eth-updown-15m)
  3. SOL (sol-updown-15m)
  4. XRP (xrp-updown-15m)

  0. Выход
============================================================
```

### Процесс работы

1. **Выбор монеты**: Введите номер монеты (1-4)
2. **Поиск события**: Бот автоматически найдет ближайшее событие в окне 0-15 минут
3. **Ожидание**: Бот дождется окончания события
4. **Определение победителя**: Автоматически определит выигравшую сторону (UP/DOWN)
5. **Клейм**: Отправит gasless транзакцию на клейм выигрыша
6. **Повтор**: Автоматически начнет поиск следующего события

### Остановка

- Нажмите `Ctrl+C` для возврата в меню выбора монеты
- Выберите `0` для выхода из программы

## Логика работы

### Поиск событий

Бот каждые 5 секунд опрашивает Gamma API Polymarket для поиска активных событий:
- Фильтр по slug prefix (например, `btc-updown-15m`)
- Временное окно: от 0 до 15 минут до окончания
- Автоматический выбор ближайшего события

### Ожидание завершения

После нахождения события:
1. Извлекает `asset_ids` (token IDs) из данных события
2. Подключается к WebSocket API Polymarket
3. Подписывается на события рынка для этих `asset_ids`
4. Ожидает сообщения с полем `winning_asset_id`
5. Получает информацию о завершении в реальном времени
6. При разрыве соединения автоматически переподключается с экспоненциальной задержкой (1, 2, 4, 8... до 60 сек)

### Определение победителя

Победитель определяется из WebSocket сообщения `market_resolved`:
- Поле `winning_asset_id` содержит ID выигравшего токена
- Бот находит индекс этого токена в списке `asset_ids`
- Индекс 0 → UP/YES
- Индекс 1 → DOWN/NO

### Клейм

Использует Polymarket Relayer для gasless транзакций:
1. Кодирует вызов `redeemPositions` для CTF контракта
2. Создает SafeTransaction
3. Отправляет через RelayClient
4. Возвращает transaction hash

## Технические детали

### API Endpoints

- **Gamma API**: `https://gamma-api.polymarket.com/events`
  - Параметры: `active=true`, `closed=false`, `limit=500`, `order=endDate`
- **WebSocket API**: `wss://ws-subscriptions-clob.polymarket.com/ws/market`
  - Используется для получения `market_resolved` сообщений в реальном времени

### Smart Contracts

- **CTF Exchange**: `0x4D97DCd97eC945f40cF65F87097ACe5EA0476045`
- **USDC (Polygon)**: `0x2791Bca1f2de4661ED88A30C99A7a9449Aa84174`
- **Relayer**: `https://relayer-v2.polymarket.com`

### Временные параметры

- Поиск событий: каждые 5 секунд
- WebSocket heartbeat: 30 секунд
- Ожидание сообщения с `winning_asset_id`: до момента получения (без таймаута)
- Пауза между циклами: 2 секунды

### Механизм переподключения

- Начальная задержка: 1 секунда
- Экспоненциальный рост: 1 → 2 → 4 → 8 → 16 → 32 → 60 секунд
- Максимальная задержка: 60 секунд
- Количество попыток: неограничено
- Сброс задержки при успешном подключении

### WebSocket Protocol

Подписка на события рынка:
```json
{
  "assets_ids": ["token_id_1", "token_id_2"],
  "type": "market",
  "custom_feature_enabled": true
}
```
> **Примечание:** Флаг `custom_feature_enabled` необходим для получения сообщений о завершении рынка с полем `winning_asset_id`.

Сообщение о завершении рынка:
```json
{
  "winning_asset_id": "76043073756653678226373981964075571318267289248134717369284518995922789326",
  "winning_outcome": "Yes",
  "market": "0x311d0c4b4671a54af4970bc6fcf58662516f5168997bda209ec3db5aa6b0c1",
  ...
}
```
> **Примечание:** Бот проверяет **только наличие поля `winning_asset_id`** в сообщении, тип события (`event_type`) не имеет значения.

## Отличия от старой версии

### Старая версия (claim.json)
- Требовала ручное добавление событий в `claim.json`
- Работала с уже завершенными событиями
- Проверяла файл каждые 60 секунд

### Новая версия (автономная)
- Полностью автоматический поиск событий
- Мониторинг текущих событий в реальном времени через WebSocket
- Мгновенное получение результатов по `winning_asset_id`
- Автоматическое определение победителя
- Бесконечный цикл без необходимости ручного вмешательства
- Автоматическое переподключение при разрыве WebSocket соединения
- Экспоненциальная задержка между попытками (1→2→4→8...→60 сек)
- Возможность выбора монеты через интерактивное меню
- Нет опроса API - все данные в реальном времени
- Устойчивость к сбоям сети
